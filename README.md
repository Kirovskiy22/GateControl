# Gate Control

Управление шлагбаумом через SNMP (SNR-ERD-2.3).

## Установка

```bash
pip install -r requirements.txt
```

## GUI (desktop)

```bash
python main.py
```

## Веб-интерфейс

Запуск локального веб-сервера:

```bash
python web_server.py
```

или:

```bash
python -m web.app
```

По умолчанию сервер слушает `0.0.0.0:8080` (см. `web_host` / `web_port` в `config.json`).

Откройте в браузере:

- на этом ПК: http://localhost:8080
- из офисной LAN/VPN: http://<IP-этого-ПК>:8080

### Безопасность

Для MVP аутентификация не реализована — сервер рассчитан на доверенную офисную LAN/VPN. Не выставляйте порт в интернет без дополнительной защиты.

### Доступ из интернета (проброс порта)

Если `http://localhost:8080` работает, а по внешнему IP роутера — нет, проверьте по порядку:

1. **Проброс порта на роутере** — нужен **TCP 8080** (веб GateControl), **не UDP 161** (это SNMP к ERD внутри LAN).
2. **Правильный IP ПК** — проброс должен указывать на LAN-адрес этого компьютера (в `config.json` поле `ip` — адрес ERD, не ПК). Узнать IP ПК: `ipconfig` → IPv4.
3. **Брандмауэр Windows** — разрешите входящие подключения на TCP 8080 (Панель управления → Брандмауэр → Дополнительные параметры → Правила для входящих подключений).
4. **Сервер слушает все интерфейсы** — в `config.json` должно быть `"web_host": "0.0.0.0"`. Проверка:
   ```bash
   netstat -an | findstr ":8080"
   ```
   Ожидается строка `TCP 0.0.0.0:8080 ... LISTENING`.
5. **Тест снаружи LAN** — проверяйте с мобильного интернета (LTE), а не из той же Wi‑Fi сети. Hairpin NAT на многих роутерах не работает: внешний IP изнутри LAN часто недоступен.
6. **CGNAT у провайдера** — если «белый» IP не выдан (адрес в диапазоне 100.64.x.x или совпадает с WAN роутера и другими абонентами), прямой проброс порта невозможен без VPN/туннеля (Tailscale, WireGuard и т.п.).
7. **Двойной NAT** — модем провайдера + ваш роутер: проброс нужен на обоих устройствах или режим bridge на модеме.

## Конфигурация

Файл `config.json`:

| Ключ | Описание |
|------|----------|
| `ip`, `port`, `community`, `oid_do1` | SNMP-параметры устройства |
| `do1_mode` | `hold` или `pulse` |
| `web_host` | Адрес привязки веб-сервера (по умолчанию `0.0.0.0`) |
| `web_port` | Порт веб-сервера (по умолчанию `8080`) |
| `rtsp_url` | RTSP-адрес камеры, например `rtsp://user:pass@192.168.1.64:554/Streaming/Channels/101` |
| `anpr_enabled` | Включить разбор потока и автооткрытие по номеру |
| `anpr_min_confidence` | Минимальная уверенность OCR (0–1) |
| `anpr_frame_interval_sec` | Пауза между кадрами, которые отдаются в распознавание |
| `anpr_open_cooldown_sec` | Пауза после открытия, чтобы один и тот же номер не слал команды повторно |
| `anpr_whitelist_only` | `true` — открывать только номера из `anpr_allowed_plates` |
| `anpr_require_valid_format` | Открывать только если номер похож на российский ГРЗ |
| `anpr_open_on_detect` | `false` — только распознавать и писать в журнал, без открытия |
| `anpr_allowed_plates` | Белый список номеров (`["А123ВС77", "В456ОР199"]`) |
| `anpr_rtsp_transport` | Транспорт RTSP: `tcp` (рекомендуется на Windows) или `udp` |
| `anpr_resize_width` | Ширина кадра перед распознаванием (`0` — без уменьшения) |

## Распознавание номеров (RTSP)

Работает в веб-сервере (`python web_server.py`): кадры с камеры разбираются в фоне, и при уверенном номере вызывается тот же `open_gate()`, что и кнопка «Поднять».

1. Укажите `rtsp_url` камеры в `config.json`.
2. Поставьте `"anpr_enabled": true`.
3. Перезапустите веб-сервер. Первый запуск скачивает модели ALPR (нужен интернет).
4. Для доступа только своих машин заполните `anpr_allowed_plates` и включите `"anpr_whitelist_only": true`.

Пока белый список пуст и `anpr_whitelist_only` выключен, шлагбаум откроется по любому распознанному российскому номеру. На странице видны статус камеры, последний номер и превью кадра.

Как устроены камера, аналитика кадра и SNMP, см. [ARCHITECTURE.md](ARCHITECTURE.md).
