# Gate Control — ESP32 START controller

Основной backend управляет ESP32D/WT32-ETH01 по HTTP. Физически подключён один выход IO4 к входу START привода NS800N. Вход START трактуется приводом как переключающий: повторный импульс может остановить или изменить текущее движение. Gate Control не знает реального положения ворот, если отдельная обратная связь не установлена.

## Управление

- `POST /api/open` → HTTP `GET /open` на ESP32: короткий импульс на IO4 / START.
- `POST /api/stop` → HTTP `GET /stop`: ESP32 снимает активные выходы. Это не гарантирует остановку двигателя, поскольку физический вход STOP не подключён.
- `POST /api/close` → HTTP 409: отдельный CLOSE не подключён и не имитируется отдельным пином.
- `GET /api/status` → опрос `/status` ESP32. Статус сообщает связь и состояние прошивки, но не позицию створки/ворот.
- ANPR при уверенном совпадении с whitelist вызывает тот же `open_gate()` и отправляет один импульс START.

ESP32 URL задаётся в `config.json` ключом `esp32_base_url`. Токен берётся только из переменной среды `GATECONTROL_ESP32_TOKEN`, не хранится в репозитории. Таймаут и cooldown задаются `esp32_timeout_sec` и `esp32_command_cooldown_sec`.

## Безопасность

Автоматическое закрытие отключено по умолчанию: отсутствие распознанного номера не является доказательством свободного проезда. До включения любых автоматических движений следует проверить фотоэлементы, концевики, штатную автоматику безопасности и работу привода на месте. Веб API следует держать в доверенной LAN/VPN и закрыть от публичного доступа.

## ANPR

RTSP capture и ALPR выполняются в `services/anpr_worker.py`; нормализация и whitelist policy — в `services/plate.py`. ANPR открывает ворота только при настройках порогов/whitelist, затем применяет cooldown против повторных импульсов. Веб-панель показывает распознанный номер, состояние камеры и журнал. Положение ворот остаётся неизвестным без датчика обратной связи.
